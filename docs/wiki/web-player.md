# Browser replay player

A userscript adds a video icon next to scenarios that have a recorded replay on benchmark websites; the icon opens a popup over the page that plays the clip. Everything is read from disk by the userscript manager, so it works while the app is not running and nothing is sent anywhere.

## Parts

- `Core/Web/ReplayWebFiles.cs`: writes two files into `cache/web/` (both rebuilt from the archive, so they are cache):
  - `replays.js`: `window.KC_REPLAYS = [...]`, the replays that have a video (id, scenario, score, end time, video file address).
  - `replay-player.user.js`: the userscript. The folder address, the `@match` lines (one site list, `ReplayWebFiles.Sites`) and `@version` (see below) are filled in when it is written. `@updateURL` and `@downloadURL` point at the same file, so the userscript manager's own update check (Tampermonkey: every 24 h by default, or "Check for userscript updates") replaces the installed copy after an app update. Updating from a `file://` address is not documented by the managers; check it on a real install when this changes.
- `@version` is a plain whole number written in `replay-player.user.js` itself (`15`, `16`, ...). Raise it by one in every commit that changes the script, so the userscript manager sees a newer script even when the app version did not change; a change without a raise is never offered as an update. It is independent of the app version. A copy installed from the short-lived `13.x.y.z` numbering is higher than any whole number below 13.x; reinstall it once.
- The app rewrites both files when it starts and whenever a replay is saved or a video is deleted.
- Settings has a four-step guide: Tampermonkey store links (Chrome, Edge), the extension switches (with an image), the "Install userscript" button (writes the script and opens it in the default browser through `DefaultBrowser`, where the userscript manager offers to install it), and the folder pick (with an image). The images are drawn illustrations in `Assets/guide-*.png`, not screenshots; redo them if the popup look changes.
- The script reads the list with `@resource` (the userscript manager's copy; it can serve an old one for a while, so a new replay's icon may appear only in a new tab) and, once the browser already allows the picked folder (no prompt), also from `cache/replays.cache` in that folder (`ReplayWebFiles.IndexCopyName`, same text as `replays.js`), read again every 5 s and whenever the page gets focus, so new icons appear without the manager. It finds scenario names in the page text and adds the icon. The popup is a shadow-root overlay with the video on the left and a date/score list on the right; the card is as tall as the video.
- The popup speaks the browser's language (`navigator.languages[0]`, two letters). `T` looks the English text up in `i18n[lang]` and shows the English text when there is no entry, so a new text needs an entry in `Strings_ko.resx` (the same file the app uses). `F` fills `{0}`, `{0:0}`, `{0:0.00}` and `{0:P0}`. The advice is written by the app as a format string plus figures (`ReplayWebOverview`, `advice: [{f, a}]`) and worded in the popup, so it follows the browser too. Dates and numbers use the browser's own locale.
- The popup takes the page's own look when it opens (`siteTheme`): the first opaque background from `body` outwards (a canvas turns any CSS color into rgb; with none it follows `prefers-color-scheme`), the `body` text color (flipped to black or white when it has under 3:1 contrast with that background) and the `body` font family. Dimmed text, hover and selected rows are mixed from those with `color-mix`. The video area and the notes over it stay dark.
- Under the video the popup shows what the app wrote for the replay (`ReplayWebStats`, `<data root>\cache\<replay id>.cache`, JSON text; the `.cache` extension marks it as rebuildable, files of another `Version` are rewritten and files of replays without a video are deleted): a run chart (accuracy, score, kills, shots, hits and mouse speed per second, one chip per figure with its value at the playhead, a tick per kill, the playhead follows the video and drags to seek; the chosen figures are kept in `localStorage`) and the "This run" / "Average" tables. The averages and the rank come from `runs` in `replays.js` (every local run of the scenario, also those whose video is gone). Also drawn from the same files: the trail over the video (the last second of the camera path projected with the run's field of view; green for a hit shot, red for a miss, red-to-green by held accuracy while the button is held, grey otherwise; the shot outcomes and held accuracy are derived in C# by `ShotClassifier` and `HeldAccuracy` and only drawn by the popup; the Trail button or T toggles it), a compare chart (the running figure of this run against the average and the best run of the scenario, second by second; it reads the files of the scenario's replays that have a video, so runs whose video is gone are not in it) and a mouse-speed card (this run against the mean of the top and bottom 5% of the scenario's runs by score, from the speed row of `runs` in `replays.js`). The first row of the list is the scenario overview, which replaces the video: totals (time, runs, best, PBs, accuracy, TTK), the advice, the score history of every run (local and cloud scores) with the other figures as toggle lines, the score by sensitivity and the mouse-speed card (top 5%, average and bottom 5%). It reads `cache/scenario-<16 hex of the SHA-1 of the lower-case scenario name>.cache`, which `ReplayWebOverview` builds from the same `ScoreBook`, `ScenarioInsights` and `ScenarioAdvice` the app's overview uses (so the advice and its permutation tests are the app's, not a port). Not in the popup: the tier bands and tier colors (they come from the app's benchmark data), and anything else the app's windows show.
- `replays.js` is `window.KC_REPLAYS={dir, items, runs, i18n}`: `dir` is the videos folder, each item's `video` is a forward-slash path inside it. `i18n` is the app's language files (`L.Tables()`: language code, then English text to translation).
- The clip comes from a folder the user picks in the browser (`showDirectoryPicker`, read-only). The handle is kept in the page's IndexedDB (one pick per site); a saved handle needs its permission asked again after a browser restart, which happens on the next click. The userscript walks `video` inside the folder, takes the `File` and plays it from `URL.createObjectURL(file)`. A file-backed blob is read lazily, so playback starts at once. A missing file shows the folder dialog again with the expected path.
- "Continue in app" navigates to `kovaaks-companion://open?id=<replay id>&s=<video seconds>`. The app registers the scheme for the current user at start (`ProtocolHandler`); a second launch hands the link to the running instance (`App.xaml.cs`), or starts the app when it is not running, and the replay popup opens at that time (`ReplayLink`, `AppHost.OpenLink`).

## What the user has to allow

- The userscript manager must be allowed to run user scripts (Chromium browsers: the extension's "Allow user scripts" switch) and to read file addresses (the extension's "Allow access to file URLs").
- A browser with `showDirectoryPicker` (Chrome, Edge); the user picks the videos folder once per site from the popup. Tampermonkey's "Allow scripts to access local files" is not needed: its default ("Externals") already lets `@resource` read the list.

## Why it is built this way

- A web page cannot load a file address with any tag (`iframe`, `embed`, `object`, `video`, `img`, a link) or open a window on one, and a popup opened by the page cannot be sent there afterwards. A folder the user picks is readable by the page.
- Earlier versions served the replays from a loopback HTTP server (needs the app running and the browser's local network permission), opened a `file://` player page in a tab, and then read each clip with `GM_xmlhttpRequest` into a blob (needed Tampermonkey's "All local files", and read the whole clip first: a 375 MB, 70 s, 2560x1440 clip took about 19 s to start). All were dropped.
- `@resource` for the videos was ruled out: resources are listed in the script header (a new replay would need a rewritten, reinstalled script) and `GM_getResourceURL` returns a base64 data URL of the whole file.

## Testing notes

- A tab with `visibilityState` hidden never loads media; activate the tab before judging a video test.
- Headless browsers refuse prompts; use a window with a fresh profile to see real ones.
- Settings in Tampermonkey's options page change with real key presses plus the Save button; a script-fired `change` event is not saved.
